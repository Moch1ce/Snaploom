# Snaploom v1 产品与实现规格

状态：已发布为 [GitHub Issue #1](https://github.com/liuchuana/Snaploom/issues/1)，标签为 `ready-for-agent`

## Problem Statement

桌面用户经常需要快速截取当前屏幕中的一个窗口或矩形区域，并立即添加矩形、箭头、文字或马赛克标注。现有工具可能过重、跨平台体验不一致，或在启动速度、安装体积、内存占用与隐私方面不符合预期。

Snaploom 需要为 Windows 10/11 与 macOS 提供一套接近微信截图交互的轻量截图体验：用户按下全局快捷键即可进入截图，在当前显示器中吸附窗口或自由框选，完成必要标注后复制或保存 PNG。截图内容必须只在本机处理，不上传、不保留历史。

## Solution

Snaploom 是一个常驻系统托盘或菜单栏、没有主窗口的桌面截图应用。它使用平台原生能力获取屏幕与窗口信息，以 Avalonia 承载设置、托盘和截图浮层 UI，并通过单个自绘画布完成截图预览、选择、标注和导出。

v1 聚焦一条可靠且高性能的核心路径：全局快捷键 → 当前显示器截图 → 窗口吸附或矩形框选 → 矩形、箭头、文字、马赛克标注 → 复制或保存 PNG → 退出截图。Windows 与 macOS 保持一致的领域行为，同时分别适配系统权限、快捷键、剪贴板、保存对话框、打包与签名机制。

## User Stories

1. 作为 Windows 用户，我希望按 `Alt+Shift+A` 开始截图，以便不打开主窗口就能快速捕获内容。
2. 作为 macOS 用户，我希望按 `Command+Shift+A` 开始截图，以便获得符合平台习惯的操作。
3. 作为用户，我希望能在设置中修改全局快捷键，并在快捷键冲突时收到明确提示，以便避开其他软件的占用。
4. 作为用户，我希望截图进行中再次按快捷键时不会打断当前操作，以免误触导致状态混乱。
5. 作为用户，我希望重复启动 Snaploom 时复用已有进程并立即开始截图，以便任何入口都只有一个应用实例。
6. 作为用户，我希望 Snaploom 常驻系统托盘或菜单栏且没有主窗口，以减少桌面干扰。
7. 作为用户，我希望从托盘或菜单栏手动开始截图，以便在不使用快捷键时仍能操作。
8. 作为用户，我希望从托盘或菜单栏进入快捷键设置、配置开机启动或退出应用，以便管理常用行为。
9. 作为用户，我希望开机启动默认关闭，以便由我决定是否让应用随系统启动。
10. 作为首次使用的 macOS 用户，我希望看到屏幕录制权限引导，以便正确完成系统授权。
11. 作为权限缺失的 macOS 用户，我希望看到可执行的修复入口，以便快速进入正确的系统设置页面。
12. 作为用户，我希望截图只发生在鼠标当前所在的显示器，以便多显示器环境中的行为可预测。
13. 作为用户，我希望鼠标悬停窗口时看到吸附高亮，以便知道即将选择的范围。
14. 作为用户，我希望单击被高亮的窗口即可选中它，以便快速完成窗口截图。
15. 作为用户，我希望从空白处拖动能够自由创建矩形选区，以便截取窗口的一部分。
16. 作为用户，我希望轻微手抖不会把单击误判为拖动，以便窗口吸附可靠。
17. 作为用户，我希望过小的矩形选区不会被创建，以避免生成无意义图片。
18. 作为用户，我希望吸附对象只包括正常可见的顶层应用窗口，以便排除系统浮层和临时窗口。
19. 作为用户，我希望最小化、隐藏、零尺寸、透明或点击穿透窗口不参与吸附，以便目标列表符合视觉结果。
20. 作为用户，我希望工具提示、菜单、拖放预览、任务栏、Dock 和菜单栏不参与窗口吸附，以便不会误选系统界面。
21. 作为用户，我希望点击桌面空白区域时选择当前显示器全屏，以便快速截取整个显示器。
22. 作为用户，我希望窗口截图包含标题栏和边框但不包含系统阴影，以便输出边界干净。
23. 作为用户，我希望窗口截图反映屏幕当前可见的内容，包括被其他窗口遮挡的结果，以便截图与眼前画面一致。
24. 作为用户，我希望输出图片中不包含鼠标指针，以便得到干净的截图。
25. 作为用户，我希望安全桌面、锁屏、受保护内容或权限不足时收到清楚的失败提示，而不是让应用请求管理员权限。
26. 作为用户，我希望框选时看到放大镜和选区尺寸，以便精确对齐边缘。
27. 作为用户，我希望工具栏默认出现在选区右下方，并在空间不足时自动翻到上方，以便始终可见。
28. 作为用户，我希望开始标注后工具栏保持稳定，不因选区微调而跳动，以便连续操作。
29. 作为用户，我希望在标注后仍能调整选区边缘，以便修正截图范围。
30. 作为用户，我希望调整选区时标注保持原有屏幕坐标，超出新选区的部分被裁切，以便行为简单且可预测。
31. 作为用户，我希望按 `Esc` 能依次取消文字编辑、当前选择、当前绘制或整个截图，以便按状态逐层退出。
32. 作为用户，我希望用矩形轮廓标记区域，以便突出内容而不遮挡底图。
33. 作为用户，我希望用单头实线箭头指向目标，以便清晰表达方向。
34. 作为用户，我希望添加多行文字，并能输入中文、英文、数字和常用符号，以便说明截图内容。
35. 作为用户，我希望用自由手绘的像素化马赛克遮挡敏感内容，以便保护隐私。
36. 作为用户，我希望用 `V`、`R`、`A`、`T`、`M` 切换选择、矩形、箭头、文字和马赛克工具，以便提高标注效率。
37. 作为用户，我希望新建标注后还能重新选中它，以便继续修改。
38. 作为用户，我希望移动或缩放矩形和箭头，并修改其颜色与线宽，以便修正标注。
39. 作为用户，我希望移动文字、修改颜色与字号，并通过双击重新编辑，以便修正文案。
40. 作为用户，我希望移动、删除或修改马赛克强度，以便修正遮挡范围。
41. 作为用户，我希望按 `Delete` 或 `Backspace` 删除选中的标注，以便快速清理。
42. 作为用户，我希望点击空白处或按 `Esc` 取消对象选择，以便返回普通操作。
43. 作为用户，我希望新建对象出现在最上层，点击重叠标注时选中最上方对象，以便交互符合视觉层级。
44. 作为用户，我希望撤销和重做标注操作，以便安全试错。
45. 作为用户，我希望矩形和箭头有红、黄、绿、蓝、黑、白六种颜色，以便适配不同底图。
46. 作为用户，我希望新标注默认使用红色并记住最近使用的颜色，以便减少重复设置。
47. 作为用户，我希望线宽提供 2、4、8 个逻辑像素三档，以便快速选择细、中、粗样式。
48. 作为用户，我希望文字提供 16、24、32 个逻辑像素三档，以便适配不同截图尺寸。
49. 作为用户，我希望马赛克画笔提供 16、32、64 个逻辑像素三档，以便处理不同大小的敏感区域。
50. 作为用户，我希望文字使用系统无衬线字体，以便跨平台保持自然且不额外打包字体。
51. 作为用户，我希望 emoji 能在系统支持时正常显示，以便常用字符尽可能可用。
52. 作为用户，我希望按 `Enter` 或双击选区复制最终图片并退出，以便最快完成截图。
53. 作为用户，我希望按 `Ctrl+C` 或 `Command+C` 复制图片并退出截图浮层，以便立即完成截图。
54. 作为用户，我希望按 `Ctrl+S` 或 `Command+S` 打开系统原生另存为对话框，以便选择保存位置。
55. 作为用户，我希望 v1 只保存 PNG，以便保持无损且避免格式选择负担。
56. 作为用户，我希望应用记住上次保存目录，以便连续保存时减少导航。
57. 作为用户，我希望默认文件名包含本地日期和时间，以便文件自然排序且容易识别。
58. 作为用户，我希望取消保存后回到原来的截图和完整编辑历史，以免误触导致工作丢失。
59. 作为用户，我希望保存成功后自动退出截图，以便流程明确结束。
60. 作为高 DPI 用户，我希望导出图片使用真实物理像素，以便图片分辨率与屏幕实际捕获一致。
61. 作为用户，我希望导出的 PNG 是 8 位 sRGB 且不包含设备、用户、路径或时间等元数据，以便兼容常用软件并保护隐私。
62. 作为重视隐私的用户，我希望截图像素和标注内容始终只在本机内存中处理，以便内容不会上传。
63. 作为重视隐私的用户，我希望应用不保存截图历史，复制时不落盘，退出截图后释放图像内存，以便减少数据残留。
64. 作为用户，我希望应用不收集遥测、截图内容或标注文本，以便使用行为不被跟踪。
65. 作为用户，我希望通过设置中的“检查更新”按钮主动查询新版本，以便自行控制网络访问。
66. 作为用户，我希望检查到新版本时看到版本号和更新说明，并能在浏览器打开 GitHub Releases，以便自行下载安装。
67. 作为用户，我希望应用不在后台自动下载或安装更新，以便避免不可见的系统修改。
68. 作为遇到问题的用户，我希望应用保留有限的滚动日志，并能在设置中打开或清除日志，以便排查故障。
69. 作为重视隐私的用户，我希望日志不记录图像像素、标注文字或完整文件路径，以便诊断信息不会泄露内容。
70. 作为用户，我希望后台故障通过系统通知提示，截图中的故障在浮层内临时显示，以便错误出现在合适的上下文。
71. 作为中文用户，我希望界面支持简体中文，以便自然使用。
72. 作为英文用户，我希望界面支持英文，并在缺少翻译时回退英文，以便始终看到可理解的文本。
73. 作为用户，我希望设置与托盘菜单跟随系统明暗主题，以便融入桌面环境。
74. 作为截图用户，我希望截图遮罩固定为深色半透明效果、工具栏边界清晰，以便在各种底图上都可辨认。
75. 作为 Windows 10 用户，我希望 Snaploom 在 Windows 10 22H2 x64 上可用，以便无需升级 Windows 11。
76. 作为 Windows 11 用户，我希望 Snaploom 支持当前 x64 系统，以便正常安装和运行。
77. 作为 Apple Silicon 用户，我希望 Snaploom 在 macOS 14 及更高版本上运行，以便获得原生体验。
78. 作为 Windows 用户，我希望使用不需要管理员权限的按用户安装包，以便自行安装。
79. 作为 macOS 测试版用户，我希望通过带 SHA256 和未认证提示的 Apple Silicon DMG 安装，以便理解 Gatekeeper 手动放行步骤并验证文件完整性。
80. 作为从 GitHub Releases 下载 Windows 测试版的用户，我希望看到 SHA256 校验值和未签名提示，以便理解 SmartScreen 警告并验证文件完整性。

## Implementation Decisions

### 平台与技术栈

- 使用 .NET 10 LTS 与 Avalonia 构建跨平台桌面应用。
- v1 支持 Windows 10 22H2 x64、Windows 11 x64，以及 macOS 14+ Apple Silicon。
- 暂不支持 Windows ARM64、Intel Mac 和 Linux。
- 首先稳定常规 self-contained 发布，再比较 NativeAOT 的兼容性、体积与性能；架构和依赖选择应保持 AOT 友好，但 NativeAOT 不是 v1 硬性门槛。
- 产品命名约定为：根命名空间 `Snaploom`、Windows App ID `Snaploom.Desktop`、macOS Bundle ID `com.snaploom.app`、发布文件前缀 `snaploom`、配置目录名 `Snaploom`。

### 模块边界

- `Snaploom.App` 负责应用生命周期、托盘或菜单栏、设置界面、截图浮层和组合根。
- `Snaploom.Core` 负责截图会话状态机、选区规则、坐标转换、标注对象、命令历史和快捷键语义，不依赖具体平台 UI 或捕获 API。
- `Snaploom.Rendering` 负责单画布渲染、马赛克处理、最终合成和 PNG 导出。
- `Snaploom.Platform.Abstractions` 定义全局快捷键、屏幕捕获、窗口枚举、剪贴板、系统权限、系统通知、保存对话框、开机启动、单实例和外部浏览器等平台能力。
- Windows 与 macOS 平台模块只实现平台抽象，不承载产品业务规则。
- 使用手工组合依赖，不引入大型依赖注入容器。
- 设置与托盘等常规界面可使用 `CommunityToolkit.Mvvm` 源生成器；截图浮层使用显式状态机，不把复杂交互隐藏在通用 ViewModel 约定中。

### 截图与窗口吸附

- 截图范围限定为鼠标当前显示器，不支持跨显示器选区。
- 使用 4 个逻辑像素作为单击与拖动的判定阈值。
- 自由选区最小尺寸为 8×8 物理像素。
- 窗口吸附只考虑可见顶层正常窗口，并排除 Snaploom 自身窗口、隐藏或最小化窗口、零尺寸窗口、工具提示、菜单、拖动预览、任务栏、Dock、菜单栏、透明或点击穿透窗口。
- 点击桌面空白区域时选择当前显示器的完整范围。
- 窗口捕获包含客户区、标题栏与边框，不包含系统阴影；捕获结果以屏幕当前可见像素为准，不尝试恢复被遮挡内容。
- 输出不合成鼠标指针。
- 不尝试捕获 UAC 或其他安全桌面、锁屏、DRM 受保护内容，也不为截图请求管理员提权。
- Windows 使用 C# 调用 Win32、WinRT 与 Windows Graphics Capture 等系统能力。
- macOS 使用薄 Swift 或 Objective-C 动态库访问 ScreenCaptureKit、AppKit、屏幕录制权限和窗口枚举，通过稳定 C ABI 与 C# 源生成的 `LibraryImport` 互操作。原生桥接层不得包含业务规则。

### 截图会话与交互

- 应用为单实例；第二次启动向现有实例发送“开始截图”意图后退出。
- 截图进行中再次触发快捷键时静默忽略。
- 截图浮层采用显式状态机管理空闲、悬停吸附、拖动选区、已选区、绘制、对象选中、文字编辑、保存对话框和退出等状态。
- `Esc` 根据当前状态逐层取消：先结束文字编辑，再取消对象选择或当前绘制，最后退出截图会话。
- 选区完成后允许调整边缘；标注保持屏幕坐标，不随选区缩放或平移，超出新选区的部分在导出时裁切。
- 创建标注后不允许整体移动选区。
- 工具栏优先放在选区右下方外侧，空间不足时翻到上方，并始终限制在当前显示器工作区域内；开始标注后保持位置稳定。
- 初始框选显示放大镜和尺寸，不显示 RGB 或 HEX 颜色值。

### 标注对象与绘制

- 标注采用非破坏性对象模型，底图在会话中保持只读。
- v1 工具包括选择、矩形、箭头、文字和自由手绘像素化马赛克。
- 所有截图内容、遮罩、选区、标注、控制柄和工具反馈由一个自定义 `ScreenshotCanvas` 单次绘制，不为每个标注对象创建 UI 控件。
- 渲染基于 Skia；只重绘受损区域。马赛克使用分块缓存，避免每帧重复处理整个 4K 图像。
- 新对象添加到最上层；命中测试选择最上方对象。不提供右键菜单、图层面板或重叠对象循环选择。
- 矩形只有轮廓，不支持填充或虚线。
- 箭头为单头实线，连接与端点采用圆角视觉，不支持双头箭头。
- 马赛克仅支持自由手绘像素化，不支持高斯模糊，也不支持对已有马赛克对象缩放。
- 矩形与箭头可移动、缩放并修改颜色和线宽；文字可移动、修改颜色和字号并通过双击编辑；马赛克可移动、删除和修改强度。
- `Delete` 与 `Backspace` 删除选中对象；点击空白处或按 `Esc` 取消选择。
- 对象创建、移动、缩放、属性修改、文字编辑和删除均进入可撤销、可重做的命令历史。
- 颜色预设为红、黄、绿、蓝、黑、白，默认红色，并在本机设置中记住最近颜色。不提供任意颜色选择器。
- 线宽为 2、4、8 逻辑像素；文字字号为 16、24、32 逻辑像素；马赛克画笔为 16、32、64 逻辑像素。
- 文字使用系统无衬线字体，支持中文输入法、英文、数字、符号与多行；emoji 为尽力支持，不作为跨平台像素一致性保证。

### 图像与坐标模型

- 平台捕获结果统一为 `CapturedFrame` 概念，包含物理尺寸、逻辑尺寸、DPI、像素格式、步幅和只读像素缓冲区。
- 捕获数据最多进行一次到预乘 BGRA/sRGB 工作格式的转换；内部流程不得使用 Base64、中间流或反复复制位图。
- 交互尺寸以逻辑像素定义，捕获、马赛克采样和最终导出以物理像素执行。
- 最终 PNG 使用真实物理像素尺寸。例如 150% 缩放下的 800×600 逻辑选区导出为 1200×900 像素。
- PNG 为 8 位 sRGB，不保留 HDR、Display P3 或 10 位颜色。
- 导出时移除 EXIF 及设备、用户、完整路径、捕获时间等元数据。

### 复制、保存与生命周期

- `Enter` 或双击选区将最终合成图复制到系统剪贴板并退出截图。
- `Ctrl+C` 或 `Command+C` 将最终合成图复制到剪贴板，并在复制成功后退出截图浮层。
- `Ctrl+S` 或 `Command+S` 打开系统原生另存为对话框。
- v1 只支持 PNG。默认文件名为 `Snaploom_yyyy-MM-dd_HH-mm-ss.png`，使用用户本地时间。
- 记住用户最近一次保存目录。
- 取消保存时恢复原截图、标注、选区与撤销历史；保存成功后退出截图。
- 不保存截图历史，复制操作不写入磁盘；截图会话退出后主动释放像素缓冲、渲染缓存和标注状态。

### 设置、隐私、日志与更新

- 截图和标注完全在本机处理；不上传截图，不收集遥测、截图内容或标注文本。
- 设置持久化仅保存快捷键、开机启动、最近使用的标注样式、上次保存目录、语言和主题等必要配置。
- 日志采用滚动文件，最多 5 个文件、每个最多 2 MB。
- 日志不得记录图像像素、标注文字、剪贴板内容或完整文件路径。
- 设置页提供打开日志目录和清除日志入口。
- 后台失败通过系统通知提示，并提供设置或日志入口；截图会话内错误通过浮层临时消息提示。
- 不进行后台自动更新。设置中的“检查更新”仅在用户主动点击后访问 GitHub Releases，展示新版本号和更新说明，并用默认浏览器打开下载页面。
- 不在应用内静默下载或安装更新。

### 本地化与主题

- v1 提供简体中文和英文资源，默认跟随系统语言，缺失资源回退英文。用户可在设置中切换语言。
- 所有面向用户的文本必须来自资源，不在业务代码中硬编码。
- 设置窗口与托盘或菜单栏跟随系统明暗主题。
- 截图遮罩固定使用深色半透明视觉；工具栏可以跟随主题，但必须与底图保持清晰边界。

### 分发与发布

- Windows x64 使用按用户安装的 EXE，不要求管理员权限；v1 不提供便携版。
- Windows 测试版暂不购买代码签名证书，接受 SmartScreen 警告；发布页必须提供 SHA256 和安装说明。正式商业发布前重新评估 OV 代码签名证书。
- macOS 测试版提供 ad hoc 签名的 Apple Silicon DMG，并在发布页明确说明 Gatekeeper 手动放行步骤；Developer ID 签名和公证延后到取得发布证书后完成。
- 不通过 Microsoft Store 或 Mac App Store 分发。
- GitHub Releases 是 v1 的下载和手动更新来源。
- GitHub Actions 分别在 Windows x64 和 Apple Silicon runner 上构建平台包；标签触发发布，并为所有制品生成 SHA256。
- 发布凭据，以及后续启用 Developer ID 时的签名和公证凭据，只能存放在 GitHub Secrets 中。

### 性能门槛

- 安装包大小不超过 50 MB。
- 托盘空闲内存不超过 100 MB。
- 从快捷键触发到截图浮层可交互的 P95 延迟不超过 150 ms。
- 在 4K 屏幕上进行选区移动、对象拖动和马赛克绘制时稳定达到 60 FPS。
- 4K PNG 合成并保存不超过 1 秒。
- 连续完成 20 次截图后不得出现持续性内存增长。
- 若关键指标在依赖精简和渲染优化后仍明显不达标，应重新评估纯 Rust 原生方案，而不是无限增加局部补丁。

### 实施顺序

1. 建立解决方案、截图状态机、坐标模型和平台抽象。
2. 在 macOS 完成“快捷键 → 捕获 → 浮层 → 选区 → 保存”的最小垂直切片。
3. 在复杂标注实现前，立即完成 Windows 10/11 的同一条最小路径，尽早验证平台抽象。
4. 依次加入窗口吸附、标注对象编辑、马赛克、剪贴板和设置。
5. 最后完成安装包、手动更新和测试版发布流程；Developer ID 签名、公证在证书可用后补充。

## Testing Decisions

### 测试原则与接缝

- 测试外部可观察行为，不锁定内部类结构、私有方法或具体渲染调用次数。
- 采用三个主要测试接缝：核心截图会话、最终渲染输出、平台适配层。除非真实缺陷无法在这三处复现，否则不增加更低层的专用接缝。
- 核心截图会话通过确定性的输入事件与状态快照测试，覆盖选择、坐标换算、状态转换、标注编辑和撤销重做。
- 渲染通过最终位图金图测试，覆盖矩形、箭头、文字、马赛克、裁切和不同 DPI 的物理像素导出。
- 平台适配通过真机集成测试验证全局快捷键、屏幕捕获、窗口吸附、权限、剪贴板、保存对话框和单实例行为。
- 当前仓库没有既有产品代码或测试先例；以上接缝将作为后续模块的初始测试约定。

### 核心行为测试

- 验证单击与拖动阈值、最小选区、选区边缘调整和多显示器坐标换算。
- 验证窗口候选过滤、顶层命中顺序、桌面空白全屏选择和 Snaploom 自身窗口排除。
- 验证截图会话中重复快捷键静默忽略，以及第二实例触发已有实例截图。
- 验证 `Esc` 在文字编辑、对象选择、绘制和会话级别的分层行为。
- 验证对象创建、命中、移动、缩放、属性修改、删除、撤销和重做。
- 验证调整选区后标注保持屏幕坐标并被正确裁切。
- 验证保存取消保留全部状态，保存成功与复制退出按约定清理会话。

### 渲染与导出测试

- 为矩形、箭头、文本和马赛克分别建立稳定金图，并覆盖重叠层级与选区裁切。
- 覆盖 100%、125%、150%、175% 和 200% 缩放下逻辑坐标到物理像素的转换。
- 验证 PNG 尺寸、8 位 sRGB、透明度处理和元数据清除。
- 对文字金图采用受控字体环境；emoji 仅验证不会崩溃，不要求跨系统逐像素一致。
- 验证剪贴板图像与保存 PNG 的最终合成内容一致。

### 平台与兼容性测试

- Windows 真机矩阵包括 Windows 10 22H2 x64 与 Windows 11 24H2 x64。
- macOS 真机矩阵包括 macOS 14 及后续受支持版本的 Apple Silicon 设备。
- 显示矩阵覆盖单显示器、双显示器、混合 DPI、显示器热插拔、1080p、4K 和 5K Retina。
- 场景覆盖快捷键冲突、macOS 缺少屏幕录制权限、取消保存、睡眠唤醒、重复启动和捕获失败。
- 验证 Windows 未签名安装包的用户级安装与卸载，以及 macOS ad hoc DMG 的校验值、架构、安装、启动和 Gatekeeper 手动放行说明。
- CI 在两个平台构建并运行不依赖交互桌面的测试；全局快捷键、系统权限和真实捕获保留在人工或具备桌面会话的自动化矩阵中。

### 性能与资源测试

- 在固定硬件基线记录安装包大小、空闲内存、快捷键到浮层延迟、4K 交互帧率和 4K PNG 保存时间。
- 快捷键到浮层延迟至少记录 30 个样本的 P50、P95 和最大值，验收以 nearest-rank P95 为准；计时从系统全局快捷键回调开始，到浮层完成平台配置并可交互为止。
- 连续运行至少 20 次成功复制或保存的完整截图流程；取消或直接关闭不计入循环。在每次浮层释放截图资源并强制 GC 后采样，不以单次瞬时峰值判定泄漏。
- 内存稳定性比较最后两个连续 5 次窗口的中位数，允许最多 1% 的尾段波动；超过 1% 视为仍在持续增长。macOS 使用 physical footprint，Windows 空闲使用 working set、循环使用 private memory。
- 4K 马赛克性能测试必须包含持续绘制、撤销、移动已有马赛克和最终导出。
- 自动 4K 基准中的选区状态、标注光栅和马赛克瓦片指标只是可重复的 CPU 代理；实际画布合成、显示器缩放和 60 FPS 仍必须在 4K 真机矩阵中确认，不能用状态更新时间替代。

## Out of Scope

- OCR、文字识别与翻译。
- 滚动截图或长截图。
- 截图贴屏或置顶图片。
- 录屏、GIF 和视频导出。
- 自由画笔、编号标签、形状填充、虚线矩形和双头箭头。
- 高斯模糊和其他模糊算法。
- 图层面板、右键菜单、重叠对象循环选择和高级排版工具。
- 截图历史、云同步、遥测、自动上传和分享链接。
- JPG、WebP 或其他图片格式。
- 跨显示器选区。
- UAC 安全桌面、锁屏、DRM 内容和不可见窗口内容的特殊捕获。
- Linux、Windows ARM64 和 Intel Mac。
- Windows 便携版、Microsoft Store 和 Mac App Store。
- 后台自动检查、自动下载或应用内静默安装更新。
- v1 强制 NativeAOT。

## Further Notes

- Snaploom 未来可能闭源商业化，因此所有依赖都必须经过许可证审查，不得引入要求商业应用公开源码的强传染性依赖。
- Windows 10 已超出微软面向普通消费者的主流支持范围；Snaploom 对 Windows 10 22H2 的承诺由项目自己的真机测试和兼容性修复承担。
- Windows 首批测试版没有代码签名，SmartScreen 警告属于已接受风险，但发布页面必须清楚解释验证 SHA256 与安装步骤。
- macOS 首版暂不使用 Developer ID 证书：只发布标记为测试版的 ad hoc DMG，并提供 SHA256 和 Gatekeeper 风险说明；取得证书后再启用正式签名和公证流程。
- 在开始复杂标注前必须完成 Windows 与 macOS 的同路径垂直切片，以尽早暴露平台抽象中的错误假设。
- 本规格是当前共同理解的基线。任何扩大 v1 范围或改变性能、隐私、平台支持的决定，都应先更新规格或记录架构决策。
